# 实现与运行中的问题

## 1. SCL 的二维特征不是多视图

老师示例中的 pooled representation 是 `[B,H]`。若损失直接把第二维当成 `views`，隐藏维度 768 就会被误解释为 768 个视图，含义和计算规模都不对。我把损失输入明确为 `[B,V,H]`，本次 `[B,1,H]`。同时明确使用最后一层 CLS，不把它与原示例的 pooler 表示混为一谈。

另外检查了自身配对、没有正样本的 anchor、温度和分母范围。固定平衡 batch 解决单视图同类正样本不足的问题。梯度累积只改变更新 batch，不自动解决对比候选集合太小的问题。

## 2. 验证不能沿用训练附加损失

各方法的训练总损失不在同一个数值口径上。验证时关闭 Dropout，只计算一次 CE，统一 Accuracy/F1/AUC。SCL 的 hidden states 只在需要附加损失时请求，并且不作为 Trainer 的预测结果返回。

## 3. 保存成功不等于重载正确

原环境出现过 BERT LayerNorm 的 `gamma/beta` 和 `weight/bias` 命名差异。加载时只对这些已知键做映射，禁止映射碰撞，再严格检查整个 state_dict。不能用 `strict=False` 略过缺失参数后继续报告。

LoRA 保存的是适配器和可训练模块，冻结基座仍需从相同模型 revision 获取。分类头必须一并保存。`adapter_restore.py` 检查导出键集合、形状、实际加载的张量值和 dtype，避免“适配器载入了，但分类头丢了”。

普通三组完整微调及 PEFT LoRA 的历史重载记录使用 16 条样本检查；Unsloth 用完整 5,000 条验证样本审计。不同覆盖范围在 `reload_check.json` 中保留，不把 16 条检查写成全验证集。

## 4. Unsloth 分类推理

当前依赖版本中的 Unsloth 会修改 Trainer 的预测路径。无标签的分类输入只有 token 张量，没有生成任务的 `prompt`，使用 `Trainer.predict()` 曾遇到 `KeyError: prompt`。

因此测试推理改为直接分 batch 调用分类模型 forward，仅取二分类 logits。使用 `inference_mode()`、每个 batch 的 autocast、关闭 autocast 长期缓存，将结果及时转到 CPU，避免保留计算图导致显存增长。

Unsloth 重载还需使用同一版本环境和同一 FastModel/LoRA 构造方式。原记录的全验证集检查：最大概率差约 `2.97e-8`，平均差约 `5.66e-9`，预测一致率 100%。仓库保留实际差值，而不是只看是否小于 0.02。

## 5. 提交文件检查

TSV 读取保留了 ID 的字面引号，直接写成 CSV 时 ID 可能与官方 sample 不一致。最终导出统一处理 ID，并逐行检查官方顺序。只处理标识符，不重新训练，不修改模型概率。

五份公开 CSV 使用正常的实验名称。每份 25,000 行，表头是 `id,sentiment`，sentiment 是正面概率。在线评测均已成功，分数与截图对应。

## 6. 当前局限

- 只有一个随机种子，尚未做重复实验或显著性检验。
- 超参数并未系统搜索，LoRA 的最佳训练设置可能与完整微调不同。
- Unsloth + LoRA + SCL 只完成短步测试，组合方法的正式结果还没做。
- 普通训练和 Unsloth 的依赖环境不同，不能把耗时差全部归因于框架。
- 整理后做了本地 CPU 入口测试，未再次租 GPU 重训。公开结果沿用原真实训练记录。
