# 运行说明

## 1. 已完成的结果与重新运行分开

查看这次结果不需要 GPU：读 README、`results/` 和五份 submission 即可。以下命令是重新训练或从保存权重再次导出时使用的。本次整理只做了本地离线测试，没有重新运行五组正式训练。

本项目只支持单 GPU、单进程。原来的正式实验是 AutoDL RTX 4090 D 24GB。CUDA、BF16 和 Unsloth 的完整训练路径已经在原云端环境运行过；本地整理后使用 CPU tiny BERT 测试普通训练/重载/推理入口，不能替代整理版代码的 GPU 回归验证。

## 2. 下载仓库并准备数据

```bash
git clone https://github.com/yue442/imdb-bert-scl-rdrop-unsloth.git
cd imdb-bert-scl-rdrop-unsloth
```

从 [Kaggle 官方数据页](https://www.kaggle.com/competitions/word2vec-nlp-tutorial/data) 下载 `word2vec-nlp-tutorial.zip`。登录并遵守该数据集的使用要求。不把原始数据提交到 Git。

安装好普通训练环境后运行：

```bash
python scripts/prepare_data.py /path/to/word2vec-nlp-tutorial.zip
```

结果为 `data/labeledTrainData.tsv.zip`、`data/testData.tsv.zip` 和 `data/sampleSubmission.csv`。外层 ZIP 内的 TSV 本身还在小 ZIP 里，训练代码直接读取小 ZIP，不需要再手动解压。

固定划分在 `configs/split_seed42.json`，正常应输出 20,000/5,000 和以下 hash：

```text
06f887e371de3f97f73434f068bbd75945790abf75a0d0caacf1f3b1ffe1e2f2
```

脚本检查数据内容与保存划分是否相符。不要删除这个 manifest 后重新随机划分，也不要改完文本清洗后继续引用旧结果。

原实验以 `quoting=3` 读取 TSV，评论中保留了原始引号。为了复现，我保留同一读取方式，只在导出 ID 时去掉字面引号。以后若调整清洗，需要所有方法用相同处理重新做对照。

## 3. 两套环境

普通 BERT/PEFT 和 Unsloth 用分开的环境。下面是 Linux/AutoDL 命令，按原运行记录固定版本。

```bash
conda create -n research-standard python=3.12 -y
conda activate research-standard
python -m pip install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements/standard.txt
python -m pip check
```

如果使用已有 AutoDL 镜像的 Torch，先确认确实是 `2.8.0+cu128`，再只安装其余依赖，避免误装 CPU 版本。

```bash
conda create -n research-unsloth python=3.12 -y
conda activate research-unsloth
python -m pip install torch==2.12.1 torchvision==0.27.1 --index-url https://download.pytorch.org/whl/cu130
python -m pip install -r requirements/unsloth.txt
python -m pip check
```

`results/<experiment>/environment.txt` 保存原来的 `pip freeze`。其中镜像预装包存在构建机器的 `file://` 路径，所以它是环境记录，不是可直接 `pip install -r` 的安装清单。上述精简依赖包含训练直接使用的包，剩余依赖仍由 pip 解析。精确环境复现应同时核对完整 freeze；新安装不保证逐位相同。

在普通环境检查：

```bash
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.is_bf16_supported())"
```

在 Unsloth 环境检查时先 `import unsloth`，再 `import torch`。两套环境均应看到 GPU 可用。无需把平台 `nvidia-smi` 的 CUDA 上限强行装成训练 CUDA 版本。

如果 Hugging Face 网络受限，可按平台提供的网络方式处理，或设置可访问的 `HF_ENDPOINT`。不要把访问 token 写进代码或仓库。基座 revision 在五份配置中已固定：

```text
86b5e0934494bd15c9632b12f734a8a67f723594
```

## 4. 先做短步测试，再做正式训练

在原 Unsloth 环境中测试自定义 SCL 路径：

```bash
conda activate research-unsloth
python scripts/run_experiment.py configs/smoke_unsloth_lora_scl.json
```

这份配置是 512 条训练/128 条验证、30 步。查看 `runs/smoke_unsloth_lora_scl/epoch_metrics.csv`，确认 `scl_loss` 非零、总损失满足 `CE + 0.2*SCL`、没有 NaN。它不生成正式提交文件，也不作为正式准确率证据。

普通环境运行四组，每条命令是一组，依次执行：

```bash
conda activate research-standard
python scripts/run_experiment.py configs/bert.json
python scripts/run_experiment.py configs/bert_scl.json
python scripts/run_experiment.py configs/bert_rdrop.json
python scripts/run_experiment.py configs/bert_lora.json
```

Unsloth 环境运行第五组：

```bash
conda activate research-unsloth
python scripts/run_experiment.py configs/bert_unsloth_lora.json
```

运行器自动在 Unsloth 子进程中设置 `UNSLOTH_COMPILE_DISABLE=1`。不要以 `torchrun` 启动，不要同时抢占同一张 GPU。需要后台运行时，可为单组使用 `nohup python ... > run.log 2>&1 &`，再查看日志和进程。

每组会写到 `runs/<experiment>/`，包含 summary、分项损失、逐轮指标、验证预测、最佳模型、环境和 `submission.csv`。脚本拒绝覆盖非空目录。重跑时显式指定新目录：

```bash
python scripts/run_experiment.py configs/bert_scl.json --output-dir runs/bert_scl_repeat
```

本次原云端记录的训练耗时约 4–6 分钟/组，不包括安装和下载。这个耗时不是对新实例的保证。

## 5. 从权重重新生成 submission

仓库不托管权重。需要先训练，或者把本地备份的 `best_model/`、对应 `summary.json` 与 `validation_predictions.csv` 放到 `runs/<experiment>/`。LoRA 目录必须包含适配器和分类头权重、adapter 配置和 Tokenizer，不能只留 LoRA 矩阵。

普通模型示例：

```bash
conda activate research-standard
python src/predict.py --run-dir runs/bert \
  --backend standard --test-file data/testData.tsv.zip \
  --sample-file data/sampleSubmission.csv --train-file data/labeledTrainData.tsv.zip \
  --output runs/submission_bert.csv
```

Unsloth 必须在原版本环境、原 FastModel 加载路径中重载：

```bash
conda activate research-unsloth
python src/predict.py --run-dir runs/bert_unsloth_lora \
  --backend unsloth --test-file data/testData.tsv.zip \
  --sample-file data/sampleSubmission.csv --train-file data/labeledTrainData.tsv.zip \
  --output runs/submission_bert_unsloth_lora.csv
```

该入口不训练。先检查保存权重的键、形状与值，再在全验证集检查重载概率，最后按原 batch 16 导出测试概率。审计保存在 `<output>.audit.json`，重载差异超过容差时停止，而不是继续提交。

`0.02` 是原实现保留的工程容差，不代表精确等价或统计检验。应同时看实际最大差异和预测一致率；本次 Unsloth 的实际差异远小于该阈值。

## 6. 提交检查

已有五份提交文件在 `submission/`：

```bash
python scripts/validate_submissions.py --sample-file data/sampleSubmission.csv
```

必须满足：表头恰为 `id,sentiment`、25,000 行、ID 唯一、顺序和官方 sample 完全一致、概率有限且在 [0,1] 内。CSV 中的 sentiment 是正面概率，而非四舍五入后的标签。上传时逐个选择 CSV，不上传整个 ZIP。

已有五份文件已提交成功。不要反复根据 Kaggle 测试分数选择超参数；改动先由训练/验证集决定。

## 7. 本地检查和重新绘图

普通环境运行：

```bash
python -m unittest discover -s tests -v
python scripts/analyze_results.py --results results --output results/figures
```

测试包含随机初始化 tiny BERT 的 CE/SCL/R-Drop/LoRA 训练、严格重载、验证审计和提交导出。不需要下载 BERT 权重，不含真实 IMDB 性能测评。图和配对错误统计只使用已保存的正式结果。
