# 本次任务运行说明

## 1. 运行平台与任务安排

这次我在 AutoDL 上租用了一张 RTX 4090 D 24GB，通过 JupyterLab 的终端完成环境配置、训练和测试集预测。

我沿用 IMDB 情感分类任务，统一使用 `bert-base-uncased`，完成以下五组正式实验：

1. BERT + 交叉熵，作为基线。
2. BERT + 交叉熵 + SCL。
3. BERT + R-Drop。
4. BERT + PEFT LoRA。
5. BERT + Unsloth LoRA。

此外，我对 Unsloth + LoRA + SCL 做了短步测试，检查自定义损失能否接入训练流程。这部分没有完成全量正式训练，因此没有放进五组正式结果中。

## 3. 环境配置与检查

为了避免 Unsloth 的依赖影响普通训练，我使用了两个独立环境。

| 环境 | 用途 | PyTorch | Transformers | PEFT |
|---|---|---|---|---|
| research-standard | CE、SCL、R-Drop、普通 LoRA | 2.8.0+cu128 | 5.12.1 | 0.19.1 |
| research-unsloth | Unsloth LoRA 及组合测试 | 2.12.1+cu130 | 5.5.0 | 0.21.2 |

两个环境均使用 Python 3.12。Unsloth 版本为 `2026.9.14`，Unsloth Zoo 版本为 `2026.9.9`。

正式训练前，我检查了 GPU 是否可用、CUDA 版本、BF16 支持情况和依赖是否冲突。在 Unsloth 环境中，先导入 Unsloth，再导入 Torch 和 Transformers，并执行了简单的 GPU 矩阵运算，确认环境能够正常计算。

每组运行保存了环境版本和 `pip freeze`，对应记录保留在结果目录的 `summary.json` 和 `environment.txt` 中。

## 4. 统一训练设置

五组正式实验的共同设置如下：

| 项目 | 设置 |
|---|---|
| 基座模型 | bert-base-uncased，同一模型 revision |
| 最大序列长度 | 256 |
| 每次训练 batch | 16 |
| batch 标签构成 | 8 条正面评论、8 条负面评论 |
| 梯度累积步数 | 1 |
| 训练轮数 | 3 |
| 学习率 | 2e-5 |
| 优化器 | AdamW |
| Weight decay | 0.01 |
| 学习率调度 | 线性衰减，10% warmup |
| 参数精度 | FP32 |
| 混合精度 | BF16 |
| 最佳模型选择 | 验证集 Accuracy |

我使用相同的平衡采样方式，保证 SCL 每个 anchor 都有同类正样本，同时让其他方法使用同样的 batch 构成。

验证时，所有方法都关闭 Dropout，使用一次 forward 的交叉熵，并计算 Accuracy、F1 和 ROC-AUC。这样不会把 SCL 或 R-Drop 的附加训练损失混入验证 loss。

## 5. 正式实验的执行过程

### 5.1 BERT 交叉熵基线

首先运行普通 BERT 分类模型，使用交叉熵训练三轮，保存逐轮指标和最佳 checkpoint。

这一组作为后续 SCL、R-Drop 的比较基准。

### 5.2 BERT + SCL

我继承 Hugging Face 的 Trainer，重写 `compute_loss()`，在交叉熵之外加入监督对比损失：

```text
总损失 = CE + 0.2 × SCL
temperature = 0.07
```

对比特征取 BERT 最后一层的 CLS 表示：

```text
hidden states：[batch, sequence_length, 768]
CLS 表示：[batch, 768]
SCL 输入：[batch, 1, 768]
```

本次使用单视图，同一个 batch 中的其他同标签评论作为正样本，不同标签评论作为负样本。

训练过程中分别记录 CE、SCL 和总损失，检查附加损失是否实际参与计算。

### 5.3 BERT + R-Drop

对同一批输入进行两次带 Dropout 的 forward，分别得到两组分类输出。

训练损失由两次交叉熵的平均值和双向 KL 散度组成：

```text
CE = 两次交叉熵的平均值
KL = 两个方向 KL 散度的平均值
总损失 = CE + 1.0 × KL
```

这一组用于比较输出一致性约束与 SCL 表示约束的效果。

### 5.4 普通 PEFT LoRA

在普通训练环境中冻结 BERT 基座参数，为注意力层的 query 和 value 加入 LoRA，同时训练分类头。

本次 LoRA 设置为：

```text
r = 16
lora_alpha = 32
lora_dropout = 0
target_modules = query、value
modules_to_save = classifier
```

这一组使用交叉熵训练，主要观察准确率、可训练参数量和显存开销。

### 5.5 Unsloth LoRA

在独立的 Unsloth 环境中，使用 FastModel 加载 BERT，再挂载相同设置的 LoRA，接入自定义 Trainer 完成三轮训练。

本次没有使用 4-bit 量化，并设置：

```text
UNSLOTH_COMPILE_DISABLE=1
```

因此，这组结果反映的是本次关闭编译的 Unsloth 运行方式，不代表启用了全部优化，也不能直接用来宣称两倍加速。

## 6. Unsloth + LoRA + SCL 短步测试

我另外使用 512 条训练样本和 128 条验证样本，运行了 30 个更新步骤，检查 Unsloth、LoRA 和自定义 SCL 损失能否共同工作。

记录中的平均训练损失为：

```text
CE：约 0.73226
SCL：约 2.93698
总损失：约 1.31965
```

总损失符合 `CE + 0.2 × SCL`，说明 SCL 项参与了计算。

这部分只验证训练流程，没有完成全量三轮对照。保留的结果来自运行日志中的 summary，不作为正式性能结论。

## 7. 模型保存、重载与测试集预测

每组训练结束后，我按照验证 Accuracy 选择最佳 checkpoint，而不是直接使用最后一轮模型。

其中，SCL 的最佳模型来自第 2 轮，其余四组来自第 3 轮。

在模型重载和预测过程中，我检查了以下内容：

- BERT 参数是否完整加载，特别是 LayerNorm 参数名称是否正确对应。
- LoRA 适配器和分类头是否一并保存、加载。
- 基座模型 revision 是否与训练时一致。
- 重载后的验证概率是否与保存的预测接近。

Unsloth 的无标签分类预测曾遇到 `KeyError: prompt`。之后测试推理改为直接分 batch 调用分类模型 forward，获取 logits，不再经过该版本被修改的 Trainer 预测路径。

Unsloth 模型最终在原训练环境中重载，并在完整的 5,000 条验证数据上检查：

```text
最大概率差：约 2.97e-8
平均概率差：约 5.66e-9
预测一致率：100%
```

其他四组保留了 16 条样本的重载检查记录。不同检查范围在对应的 `reload_check.json` 中注明。

测试集预测使用最佳模型，导出正面类别的概率：

```text
sentiment = softmax(logits)[:, 1]
```

没有把预测概率四舍五入成 0/1 标签。
