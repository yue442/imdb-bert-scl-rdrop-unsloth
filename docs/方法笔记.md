# 方法笔记

## 1. 本次分类流程

评论先通过 BERT Tokenizer 变成 `input_ids`、`attention_mask` 和 `token_type_ids`。输入一般为 `[B,L]`，BERT 最后一层 hidden states 为 `[B,L,768]`，取第一个位置后是 `[B,768]`。

分类头输出 logits `[B,2]`。交叉熵使用 logits 和真实标签，Kaggle 提交使用 `softmax(logits)[:,1]`。预测标签用于 Accuracy/F1，概率用于 ROC-AUC，两者不能混用。

我这里的 SCL 特征来自 `outputs.hidden_states[-1][:,0,:]`，不是分类头 logits，也不是 `pooler_output`。BERT 默认的分类路径仍经过 pooler、Dropout 和分类头。因此分类分支与对比分支共享 BERT，但取表示的位置不同。

## 2. SCL 为什么约束表示

交叉熵只要求模型区分标签，不直接约束同类样本之间的距离。SCL 把当前样本作为 anchor，其他同标签样本作为 positives，不同标签样本作为 negatives。在单位长度的表示上计算点积，相当于余弦相似度。

设归一化特征为 $z_i$，除自身以外的候选集合为 $A(i)$，正样本集合为 $P(i)$：

$$
L_i=-\frac{1}{|P(i)|}\sum_{p\in P(i)}
\log\frac{\exp(z_i^Tz_p/\tau)}{\sum_{a\in A(i)}\exp(z_i^Tz_a/\tau)}.
$$

对有正样本的 anchor 取平均得到 $L_{SCL}$。总损失为 $L=L_{CE}+\alpha L_{SCL}$。本次 $\alpha=0.2$、$\tau=0.07$，没有另外加投影头。

温度越小，相似度的差异在 softmax 中越明显，但不是越小越好。分母包含所有非自身样本，包括正样本；不能只放负样本。自身不能当正样本，否则会把容易的自相似混入目标。

`SupConLoss` 的输入为 `[batch, views, hidden]`。本次是单视图，所以将 `[16,768]` 用 `unsqueeze(1)` 变为 `[16,1,768]`。同一个 batch 的其他同类评论提供正样本。没有做两次增强，因此与原论文多视图的实验设置不完全相同。[SCL 论文](https://arxiv.org/abs/2004.11362)

实现时相似度和 `logsumexp` 使用 FP32，排除对角线，过滤没有正样本的 anchor。所有 anchor 都没有正样本时返回可反向传播的零值，不产生除零或 NaN。

### batch 与梯度累积

固定平衡 batch 的 16 个样本中，每个 anchor 有 7 个同类 positives、8 个 negatives。这样避免小 batch 偶然没有同类样本。

有效更新 batch = 每卡 batch × GPU 数 × 梯度累积步数。若每次 forward 16 条、累积 4 次，有效更新 batch 是 64，但普通 SCL 每次仍只比较本次 16 条。除非显式跨步保留特征或做跨卡收集，梯度累积不会扩大对比候选集合。本项目只支持单 GPU，没有跨卡收集。

## 3. R-Drop 为什么约束输出

训练时 Dropout 为相同输入提供两种随机子网络，得到 $p_1$、$p_2$。两次分别计算 CE，并用预测分布之间的 KL 限制随机差异：

$$
L_{CE}=\frac{CE(l_1,y)+CE(l_2,y)}2,
\quad L_{KL}=\frac{KL(p_1\Vert p_2)+KL(p_2\Vert p_1)}2,
\quad L=L_{CE}+\beta L_{KL}.
$$

本次 $\beta=1$。KL 使用 `batchmean`，两个方向都计算，log-softmax 与 softmax 使用 FP32。这里明确写出平均方式，因为把双向 KL 相加而不除以 2，会改变相同 beta 的实际强度。[R-Drop 论文](https://arxiv.org/abs/2106.14448)

| 对比项 | SCL | R-Drop |
|---|---|---|
| 约束位置 | 隐藏表示 | 输出概率 |
| 依赖关系 | batch 内同标签/不同标签样本 | 同一样本的两次随机输出 |
| 额外训练成本 | 表示输出与两两相似度矩阵 | 再做一次模型 forward |
| 验证方式 | 单次 forward 的 CE | 单次 forward 的 CE |

## 4. LoRA 与 Unsloth 的区别

完整微调更新全部 BERT 参数。LoRA 冻结基座矩阵，通过 $W'=W+(\alpha/r)BA$ 增加可训练的低秩更新。本次 `r=16`、`lora_alpha=32`，缩放系数为 2。目标是注意力的 query/value，分类头保留为可训练模块。[LoRA 论文](https://arxiv.org/abs/2106.09685)

LoRA 主要减少可训练参数、梯度和优化器状态，但仍需要保存激活，不能保证任意长度和 batch 都不 OOM。本次没有量化，所以不能称为 QLoRA。

Unsloth 是训练实现和优化路径，不是另一种损失。它包装模型与 LoRA，再由同一个 `ResearchTrainer.compute_loss()` 计算 CE、SCL 或 R-Drop。先导入 Unsloth，再导入 Torch/Transformers 和自定义 Trainer。

当前正式 Unsloth 实验用 CE。Unsloth + LoRA + SCL 只有 512 条训练/128 条验证、30 步的测试记录，验证了附加损失参与计算，不代表已经完成性能对照。

## 5. Trainer 中具体改了哪里

我没有改 Transformers 的安装包，修改集中在继承类：

1. `compute_loss()` 按方法选择训练损失。SCL 需要 hidden states；R-Drop 需要第二次 forward。
2. `model.training` 为 false 时只计算一次 CE，避免验证损失和训练附加项混淆。
3. 返回结果只保留 loss/logits，避免 Trainer 额外收集所有 hidden states。
4. `get_train_dataloader()` 使用相同的平衡采样器，固定随机种子并逐 epoch 改变 shuffle。
5. 记录 CE、SCL、KL、总损失，便于判断方法是否真的启用。

本次 BERT/CE 与 BERT/SCL 是“加入一个损失项”的控制实验。它能检验这套配置下的附加损失效果，但不等于完成了温度、权重、特征选择、多视图等所有消融实验。
